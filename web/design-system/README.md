# Дизайн-система для Claude Design

Язык интерфейса Takt в виде, который понимает Claude Design: токены,
книга бренда, живые компоненты, иконки. Макеты и слайды, сделанные
в Claude Design, берут цвета, шрифт и компоненты отсюда, а не
подбирают свои.

Источник — сам продукт, и сборка его не переписывает, а читает:

| Что | Откуда |
| --- | --- |
| токены обеих тем | `src/app/styles.css` (блоки `:root` и тёмной темы) |
| иконки | `src/shared/ui/icons.tsx` |
| живые компоненты | `src/shared/ui`, точка входа `entry.ts` |
| стиль превью | свежая сборка `dist/assets/index-*.css` |
| книга бренда, пояснения, превью | `content/` — написаны руками |

## Собрать

```bash
make design-system   # пересоберёт клиент и положит результат в web/design-system/out
```

В `out/project/` — дерево файлов системы, в `out/icons/` — иконки
отдельными SVG. Каталог `out/` в репозиторий не идёт.

**Сборка падает, если в `:root` появился токен, о котором она
не знает.** Это нарочно: система, молча отставшая от продукта, хуже
упавшей сборки. Новый токен вписывают в `build.mjs` с пояснением —
или в `SKIP` с причиной, почему он в систему не идёт.

## Опубликовать

Система живёт закрытым артефактом Claude Design; адрес знает
владелец. Публикует Claude Code инструментом Artifact:

1. иконки из `out/icons/` — загрузкой в хранилище системы
   (`asset: true`), каждая получает свой идентификатор;
2. перечитать с сервера `project/design-system.json` — индекс системы:
   в нём записи иконок, их меняют и со страницы;
3. одним вызовом отправить изменившиеся файлы `out/project/`
   и индекс последним, с обновлённым `lastChange`.

`tokens.css`, `manifest.json` и карточки `api/` страница делает сама —
их не пишут.

## Живые компоненты

`bundle.js` — это `src/shared/ui`, собранный esbuild в один скрипт
`window.Takt`. React в него не входит: формат системы подгружает
React 18 с jsDelivr, и `react`, `react-dom`, `react/jsx-runtime`
подменены на `window.React`. Продукт работает на React 19, но
нового из 19-го эти компоненты не используют; если начнут —
превью это покажут, а сборка нет.

Подписи обоих языков встроены в скрипт (динамические `import()`
esbuild в формате IIFE разворачивает в сам файл). `Takt.ready` —
готовность подписей, `Takt.setLang('en')` — смена языка.

Точка входа делает одно, чего в продукте нет: во фрейме превью
запись в `document.cookie` запрещена и бросает исключение, из-за
чего `loadLang` не доходил до подписей. Там cookie подменяется
пустышкой; в продукте ветка не срабатывает.

Компонент попадает в систему живым, если его превью в `content/`
рисует `window.Takt`. Метка и карточка доски остались статичной
разметкой на настоящем CSS: метка — это классы, а карточке нужен
контекст доски.

## Превью

Первая строка — `<!-- @dsCard group="…" height=N -->`. Код превью —
внутри `(() => { … })()`: без обёртки его `const` становятся
глобальными. Подписи — настоящие строки из `src/shared/i18n/ru.ts`,
а не придуманные.

Проверять глазами в обеих темах. `crypto.randomUUID` (им пользуется
`Toast`) есть только в безопасном контексте: во фрейме системы он
есть, а в `page.setContent` без https — нет, и это не поломка.
