# Публичное демо: Render + Neon

Демо для потенциальных клиентов. Каждый посетитель нажимает
«Попробовать без регистрации» и получает свою организацию с примерами
на сутки. Выкладывается само после каждой зелёной «Проверки» на master
(`.github/workflows/demo.yml`). Почему именно эти площадки и чем они
ограничены, записано в ROADMAP, этап 30.1, разбор 21.09.2026.

Заводится один раз, руками. Шаги идут в том порядке, в каком одно
нужно другому.

## 1. База: Neon

1. Заведите аккаунт на neon.com и проект: PostgreSQL 16, регион в
   Европе (например AWS Frankfurt, `aws-eu-central-1`). Render тоже
   держите во Франкфурте: каждый запрос ходит в базу, и через океан
   это заметно.
2. Откройте **SQL Editor** и выполните от роли по умолчанию:

   ```sql
   create role takt login password 'длинный-случайный-пароль'
       nosuperuser nocreaterole nocreatedb nobypassrls;
   ```
   ```sql
   grant takt to current_user;
   ```
   ```sql
   create database takt owner takt;
   ```

   Каждый запрос — отдельно и кнопкой **Run**, не **Explain**:
   Explain оборачивает запрос в `EXPLAIN` и падает с «syntax error
   at or near …». Отдельно — потому что `create database` не идёт
   внутри транзакции, а редактор склеивает несколько запросов в одну.
   `grant` нужен с PostgreSQL 16: владельцем базы можно назначить
   только роль, от имени которой можешь действовать сам. На `takt`
   он не влияет — BYPASSRLS у неё не появляется.

   Neon заводит проект на самой свежей версии (на 22.09.2026 — 18),
   а не на 16. Миграции на 18 проходят: первая выкладка шла на ней.

   **Роль — только SQL-ом, не через консоль.** Роли, заведённые
   в консоли или через API Neon, входят в `neon_superuser`, а у неё
   есть BYPASSRLS. Под такой ролью политики изоляции не действуют,
   и сервер откажется стартовать; он прав.
3. Соберите строку подключения к базе `takt` под ролью `takt`. Хост
   берите **прямой, без `-pooler`** в имени. Пулер Neon работает
   в режиме транзакций и теряет LISTEN, а на LISTEN держится обновление
   доски у всех, кто её открыл. В конце строки допишите
   `?sslmode=require`.

## 2. Образ: GitHub Container Registry

Пакет `ghcr.io/findias/takt-demo` заводит сам workflow «Демо»: образ
собирается после каждой зелёной «Проверки» на master, даже пока
секретов демо нет. Достаточно, чтобы после этой правки прошёл хотя бы
один пуш в master (или запустите **Actions → Демо → Run workflow**).
Новый пакет закрыт, а Render забирает образ без пароля, поэтому пакет
нужно открыть: **Packages → takt-demo →
Package settings → Change visibility → Public.** Делается один раз.

## 3. Приложение: Render

1. Заведите аккаунт на render.com. Карта для бесплатного тарифа
   не нужна.
2. **New → Web Service → Existing Image**, образ
   `ghcr.io/findias/takt-demo:latest` (он уже есть после шага 2).
   Имя сервиса Render предлагает из образа (`takt-demo-latest`),
   и из имени же получается адрес. Адрес для `BASE_URL` и `DEMO_URL`
   берите со страницы сервиса, а не угадывайте.
3. Тариф **Free**, регион **Frankfurt**.
4. Переменные окружения:

   | Переменная | Значение |
   | --- | --- |
   | `DATABASE_URL` | строка из шага 1.3 |
   | `BASE_URL` | адрес сервиса, `https://<имя>.onrender.com` |
   | `LISTEN_ADDR` | `:10000` — этот порт Render ждёт по умолчанию |
   | `SIGNUP` | `closed` |
   | `DEMO` | `on` |

5. **Health Check Path:** `/readyz`.
6. **Settings → Deploy Hook**: скопируйте адрес. Никому его
   не показывайте: по нему выкладывают.

## 4. Секреты в GitHub

**Settings → Secrets and variables → Actions → New repository
secret:**

| Секрет | Что положить |
| --- | --- |
| `DEMO_DATABASE_URL` | строка из шага 1.3 (по ней workflow прогоняет миграции) |
| `RENDER_DEPLOY_HOOK_URL` | Deploy Hook из шага 3.6 |
| `DEMO_URL` | адрес сервиса без `/` в конце |

Значение передавайте в самой команде:
`gh secret set DEMO_URL --body 'https://…'`. Без `--body` команда
спрашивает значение с клавиатуры, а там, где клавиатуры нет (скрипт,
`!` в Claude Code), может молча записать пустой секрет.

Затем **Actions → Демо → Run workflow**. Выкладка считается сделанной,
когда живой адрес отвечает новой версией. Workflow проверяет это сам,
заходя так же, как посетитель.

## Чего ждать от бесплатного тарифа

- **Первый посетитель после 15 минут тишины ждёт около минуты:** Render
  усыпляет сервис. Будить его пингами не надо. Сервис каждую минуту
  ходит в базу, пока не спит, и неспящий сервис съест часы Neon
  (100 CU-ч в месяц) за две недели.
- **Neon засыпает через 5 минут без запросов** и рвёт соединения.
  Сервер переподключается сам, в том числе слушатель обновлений доски.
- **Песочниц одновременно не больше 300**, новых не больше 30 в час
  на всех. Упёрлись — посетитель видит «попробуйте через час».
  Песочница весит около 190 КБ, так что 300 штук займут около 60 МБ
  из 500.
- **Подписки на события в демо выключены**: доставка ходила бы
  по любому адресу, который вписал посетитель.
