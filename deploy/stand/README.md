# Тестовый стенд ветки: Render + ветка базы Neon

Стенд показывает ветку до того, как она попала в master, а значит,
и в демо, которое видят клиенты. На каждом экране полоса «Тестовый
стенд: ветка …», а кнопка «Что на стенде» открывает коммиты ветки
поверх master: что появилось и как это проверить, на языке интерфейса.
Выложенный сам master показывает коммиты с последнего выпуска (тега):
поверх себя у него коммитов нет, а сделанного с выпуска — десятки.
Почему так устроено — ROADMAP, этап 30.7.

Выкладывается руками: **Actions → Стенд → Run workflow**, ветка на выбор
(`.github/workflows/stand.yml`). Ветку, уже влитую в master, выкладывают
с полем «От какого коммита считать» — коммитом master до вливания:
иначе коммитов поверх master у неё нет и заметка пуста (так вышло
26.09 с этапом 31). Из терминала:
`gh workflow run stand.yml -f branch=<ветка> -f base=<коммит>`. Стенд один: следующая выкладка сменяет
предыдущую.

## Как писать коммиты, чтобы стенд было что показать

Заметка стенда собирается из сообщений коммитов (правило —
`CONTRIBUTING.md`, «Language»): английский заголовок и тело, блок
`How to check:` с шагами, затем строка `--- ru ---` и то же по-русски
с блоком `Как проверить:`. Коммит без перевода или без «как проверить»
выложится, но на стенде будет помечен, а workflow об этом предупредит.

## Заводится один раз

### 1. База: ветка в Neon

В проекте демо: **Branches → New branch**, имя `staging`, родитель —
`production`. Роль `takt` с паролем копируется вместе с данными. Строку
подключения берите для базы `takt` под ролью `takt`, **без `-pooler`**
в хосте, с `?sslmode=require` в конце: пулер теряет LISTEN, а на нём
держится обновление доски.

Ветка — копия демо, поэтому в ней лежат и песочницы посетителей. Стенд
их не убирает (уборщик песочниц работает только в демо), и мешают они
только местом.

### 2. Приложение: второй сервис Render

**New → Web Service → Existing Image**, образ
`ghcr.io/findias/takt-demo:latest` (дальше workflow подставляет образ
ветки сам), тариф **Free**, регион **Frankfurt**, Health Check Path
`/readyz`. Переменные:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | строка из шага 1 |
| `BASE_URL` | адрес сервиса со страницы Render, без `/` в конце |
| `LISTEN_ADDR` | `:10000` |
| `SIGNUP` | `closed` |
| `STAND` | `staging` |

`DEMO` не задавайте: с `STAND=staging` сервер не стартует.

**Правка переменных в Render перезапускает сервис на образе из его
настроек**, то есть на `:latest` — master, а не на выложенной ветке.
Стенд после этого показывает пустую заметку и версию master. Поправили
переменную — выложите ветку ещё раз (найдено 22.09 на первой выкладке).

### 3. Секреты в GitHub

Значение передавайте в самой команде, через `--body`: без него команда
может молча записать пустой секрет.

```
gh secret set STAGING_DATABASE_URL --body 'postgresql://takt:…@ep-….neon.tech/takt?sslmode=require'
gh secret set STAGING_DEPLOY_HOOK_URL --body 'https://api.render.com/deploy/srv-…?key=…'
gh secret set STAGING_URL --body 'https://….onrender.com'
```

## Автотесты против стенда

После выкладки workflow гоняет сквозные сценарии прямо на стенде
(`web/e2e-stand/`): полоса и заметка, вход под каждой ролью, доска
с карточками, карточка, «Поток», личные настройки, наблюдатель без права
заводить. Участник заводит доску с карточкой и убирает её в архив,
поэтому в разделе «Архив» копятся доски «Автотест …»: мешают они только
там. Упал сценарий — прогон красный, а снимки и следы прикреплены
к нему артефактом «следы-стенда».

Перепроверить стенд, не выкладывая заново:

```
make stand-e2e STAND_URL=https://takt-staging.onrender.com
```

Сценарии ставят людям стенда язык явно (русский, для английской
проверки — английский и обратно): люди общие с теми, кто проверяет
руками, и выбранный кем-то английский иначе ронял бы русские проверки.

## Как войти

Люди — те же, что у локального стенда: `anna@example.test` (владелец),
`boris@`, `vera@`, `dmitry@` (участники), `gleb@` (наблюдатель), пароль
`parol12345`. Он же написан в заметке стенда: стенд не для чужих
данных, и прятать пароль от демонстрационных людей незачем. Поэтому
подписки на события на стенде выключены, как и в демо: войти может
любой, а доставка ходила бы по любому адресу.

## Если миграция ветки испортила базу стенда

Миграции идут только вперёд, и неудачную из базы не убрать. Ветку
базы сбрасывают к основной: **Neon → Branches → staging → Reset from
parent**, затем выкладывают стенд ещё раз. Основную базу, то есть демо,
это не трогает.

## Чего ждать от бесплатного тарифа

Часы общие с демо: у Render 750 часов в месяц на все бесплатные
сервисы, у Neon 100 CU-часов. Оба засыпают без посетителей, поэтому
первый заход после простоя ждёт около минуты.
