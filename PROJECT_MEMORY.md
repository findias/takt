Исходная локальная память:
`~/.claude/projects/-home-konkov-Documents-projects-agile/memory/`.
Основные сведения сверены с кодом. Исторические статусы не скопированы
как текущие; закрытые доступы и сведения об инфраструктуре не перенесены

Это файловая память проекта для следующих сессий Codex. Точка входа —
`AGENTS.md`. Изменение глобальной памяти аккаунта этим не подразумевается.

## Продукт и устройство

- Takt — частный канбан-трекер; модуль Go `github.com/findias/takt`,
  лицензия Apache-2.0. Один серверный бинарник и образ, PostgreSQL —
  единственное постоянное хранилище, включая очередь и LISTEN/NOTIFY.
- Backend: Go, pgx/v5, PostgreSQL 16+. CLI `cmd/takt`: `serve`,
  `migrate`, `demo`, `doctor`, `import`, `version`. Отдельный
  `cmd/takt-fetch` собирает пакеты переноса с внешних платформ.
- Frontend: React 19, TypeScript strict, Vite; Pragmatic Drag and Drop.
  Собственные UI-компоненты, стили и токены вместо большой UI-библиотеки.
- Слои клиента: `app → widgets → features → entities → shared`.
  Реальные импорты ограничивает `web/src/app/layers.test.ts`.
- `internal/board` — модель доски и операции; `internal/rank` —
  дробные строковые ключи порядка; `internal/auth`, `org`, `team` —
  личности, членство, организации, дерево подразделений.
- `internal/httpapi` — маршруты, обёртки доступа, контракт, OIDC/SCIM,
  раздача клиента. `internal/store` — pgx-пул, области транзакций,
  миграции; `migrations/*.sql` вшиты в бинарник.
- `internal/metrics`, `report` — поток и выгрузки; `idea` — идеи;
  `webhook`, `realtime`, `retention` — доставка и фоновая обработка;
  `importer`, `export` — перенос и выгрузка; `demo` — стенд и песочница.
- Развёртывание: Docker Compose или Helm (`deploy/helm/takt`).
  Миграции выполняются отдельным шагом, в Helm — до обновления подов.

## Инварианты данных

- Организация — арендатор. Личность `users` отделена от `memberships`;
  роль принадлежит членству, активная организация — сессии.
- Изоляция держится на PostgreSQL RLS, а не на добавлении `org_id`
  в каждый запрос. Без области транзакции данные арендаторов не видны.
  Сервер проверяет и отвергает подключение с superuser/BYPASSRLS.
- `store.BeginScope` задаёт `app.current_org`, `app.current_user`,
  хеши специальных токенов и имя служебной задачи через транзакционные
  `set_config(..., true)`. `InTenant` задаёт организацию и человека,
  `InOrg` — только организацию. Фоновой записи нужна своя политика.
- Видимости доски: `org`, `team`, `private`. Подразделения образуют
  дерево до пяти уровней; `parent_id` — источник, `ancestor_ids` —
  индексируемый путь. Права наследуются вниз без урезания.
  Наблюдение за поддеревом отдельно от роли; закрытая доска — исключение.
- Строковые `position` требуют побайтового `COLLATE "C"` (0078).
  Alpine/musl скрывает ошибки локалезависимой сортировки; для её проверки
  нужна база с настоящей ICU-локалью.
- `card_events` и `audit_events` — история, которую нельзя восстановить
  задним числом. Административный аудит пишут триггеры базы.
- Операции доски сериализуются блокировкой, отвечают версией и патчем;
  повторять следует с тем же `operationId`. Это свойство не переносится
  автоматически на отдельные HTTP-обработчики.
- Исполнителем может быть только видящий доску. Использовать
  `app_sees_board_as`, не копировать политику в код. Наблюдателя можно
  назначать исполнителем: владелец явно оставил это поведение.
- Выполненная карточка имеет 100 %; 100 % означает выполненную карточку
  (решение владельца от 29.10.2026).

## Миграции и проверка

- Применённые миграции не переписывать; схему менять только новой.
  Новая схема должна работать со старым приложением и при откате подов.
  Удаление используемого поля делать через два выпуска.
- При DML в миграции FORCE RLS без арендатора молча скрывает все строки.
  На время переноса снять `FORCE` у конкретных таблиц и вернуть сразу
  после; проверить предусловие через `pg_class`. Не ставить глобальный
  `row_security=off`. Образец — `0031_assignees.sql`.
- Проверять перенос и на базе с данными, и цепочку с нуля. Проверка
  `internal/store` создаёт отдельную базу администратором, мигрирует
  под ролью приложения и сравнивает схемы. Нужны обе переменные:
  `TEST_DATABASE_URL` и `TEST_ADMIN_DATABASE_URL`.
- Инспекция всей dev-базы — от `postgres`; под ролью приложения без
  контекста «0 строк» не означает пустую базу.
- Обычный стенд: приложение `http://localhost:8099`, PostgreSQL
  контейнер `takt-dev-db`, порт 55432, роль и база `takt`.
  Проверять наличие контейнера и порт каждый раз.
  Демо-входы и команды — в `CLAUDE.md`.
- `make stand` удаляет базу; `make demo` сохраняет существующие данные
  и доливает недостающее. Историческое утверждение «демо не меняется
  без сброса» устарело: в коде есть `TopUp`/`TopUpEnglish`.
- `make check` не строит `web/dist`; для свежего клиента нужен
  `make web-dist` или `make run`. При изменении Go перезапуск обязателен.
- Тесты моделей клиента — Node, DOM — Vitest/Testing Library,
  браузерные — Playwright. Проверять реальное состояние через API/БД:
  оптимистичный экран сам по себе не подтверждает сохранение.
- При временном доказательстве дефекта сохранить текущий файл копией;
  не откатывать опыт через `git checkout`, теряя несохранённые изменения.
- Общая очередь вебхуков и фоновые работники влияют на тесты соседей.
  Демо не должно оставлять живые доставки к недостижимым получателям.
  Нагрузочные прогоны выполнять по одному на свободной машине.

## Язык, интерфейс и документация

- Код, комментарии и исходные отказы — по-русски; комментарии объясняют
  причину. По поведению искать также русские корни и имена тестов.
  Отсутствие совпадения подтвердить чтением, прежде чем объявлять пробел.
- UI-строки — в `web/src/shared/i18n/ru.ts`, `en.ts` и разделах каталогов.
  Серверные переводы — `internal/i18n/en.go`, демо — `demo/english.go`.
  Отказы различаются кодом, не текстом. Новый код нужен в `openapi.json`
  и в тесте, который получает его реальным запросом.
- Подписи должны называть вещь и действие простыми словами. Термины
  и метрики объяснять через `Hint` и справочник, а не абзацами под
  каждым блоком. «Завести» — новое, «добавить» — существующее.
- Плотность задаёт `--scaling`; использовать токены из `styles.css`,
  обе темы, системный шрифт, контейнерные запросы для карточек.
  Архивация обратима и предлагает отмену; окончательное удаление
  объясняет последствия и подтверждается.
- Производительность сначала измерять. Проектные пороги и инструменты
  записаны в `frontend-perf/SKILL.md`; не переписывать их по памяти.
  Изменение одной карточки не должно перерисовывать соседние.
- «Как сейчас» в макете показывать свежим снимком реального стенда.
  Группировки и плотность уже существуют — перед предложениями
  свериться с продуктом. Для макетов использовать дизайн-систему Takt,
  её исходники — `web/design-system`, сборка — `make design-system`.
- Проверка вёрстки: оба языка, темы, узкие окна, реальные длинные
  названия, группы и пустые состояния. Дефекты закреплять измерениями
  `boundingBox`, фокуса и попадания клика, а не наличием узла.
- Сведения о поддержке браузерами датировать и проверять по первичному
  источнику (например, Web Platform Status), не считать записи августа
  2026 вечными. Старые способы подключения Claude к Chrome не являются
  инструкцией по доступным инструментам Codex.
- `docs/` и `README.md` — английские оригиналы; русские переводы имеют
  отпечаток исходника, который проверяет `internal/translation`.
  `docs/html` генерируется `make docs`, руками не редактируется.

## Принятые продуктовые решения

- Идеи — отдельный список организации, не карточки и не доска.
  Их подают и поддерживают все, включая наблюдателя; анонимности нет.
  «Кому» — вся организация или подразделение.
- Решает владелец организации или владелец подразделения в своём
  поддереве. «Берём» дополнительно требует записи на целевую доску.
  Исходы: `taken`, `declined` с причиной, `duplicate`, `later`.
  Решения добавляются историей; голоса двойников считаются запросом.
- Идеи через API используют `boards:read/write`; голос, перенос и
  решение — действия человека. События: `idea.created`, `idea.decided`;
  решение уведомляет автора и поддержавших. Идеи входят в XLSX/JSON.
- С исправления от 01.11.2026 карточка из идеи, описание, решение
  и уведомления сохраняются одной транзакцией. `board.ApplyInTx`
  использует транзакцию решения; `Apply` остаётся обычной обёрткой.
  Решение и перенос берут `NO KEY UPDATE` на идею и перечитывают права
  после ожидания. Команда формы несёт `requestId` (0089), который
  хранится в истории в области человека и идеи. Поздний повтор после
  другого решения возвращает нынешнее состояние без записи и побочных
  действий; другой запрос с тем же ID получает 409. После сетевой ошибки
  форма сохраняет ID, при изменении отправляемых полей заводит новый.
  Для клиентов без ID одинаковый текущему ответ распознаётся по
  `idea_decisions.request_fingerprint` (0088). Новый ID означает новое
  намерение; это позволяет намеренно принять идею повторно.
  Для старых записей без отпечатка сравниваются сохранённые поля,
  пока ссылки на карточку или другую идею доступны.
- Перенос между уровнями (0087): автор переносит свою до первого
  решения; решающий — открытую, включая «позже». Владелец подразделения
  переносит внутрь своего поддерева или на организацию, не в чужое.
  **Это ограничение предложил прежний агент без отдельного подтверждения
  владельца.** Не приписывать его явному решению пользователя.
  При переносе нет события и уведомления — осознанно оставлено так.
- «Поделиться задачей» пока означает копирование обычной ссылки.
  Публичный доступ и отправка уведомления человеку не обещаны.
- Статус эпика пишется по праву записи на его доску; записи исторические.
  Это вывод прежнего агента из прав доски, не отдельное согласование.
- Отчёты считают поток; потраченные часы и скорость отдельного человека
  не добавлять без отдельной задачи. Обещание итерации считается по
  исходному составу, добавленное позже его не расширяет.
- Перенос из внешней системы направлен внутрь Takt. Чужие даты не
  подделывать под историю наших переходов. Связки задуманы как чтение
  без обратной синхронизации; чужие токены должны шифроваться.
  Это направление и решение, а не утверждение, что все связки готовы.
- XLSX/CSV/JSON уже реализованы; XLSX пишется собственным кодом
  `internal/report/xlsx.go`. Старую запись о предполагаемой зависимости
  `excelize` не переносить как факт о текущей реализации.
- Рабочие планы и решения по предложениям живут отдельно от публичного
  кода. Их интеграция с Telegram — отдельный контур; не запускать
  сторонние опросчики и не менять его службы в ходе обычной разработки.
  Внешние записи не редактировать вне разрешённых корней файловой системы.

## История и выпуск

- История до открытия репозитория 26.08.2026 переписана; старые хеши
  из памяти могут быть недействительными. Актуальный выпуск проверять
  по тегам и CHANGELOG, не по историческим заметкам памяти.
- Выпуск: английский CHANGELOG и русский перевод, документация,
  зелёные проверки коммита, визуальные и 10-минутные нагрузочные
  проверки, затем тег. Точный порядок — `CLAUDE.md` и release workflow.
- Версия вшивается через `git describe`. Поставка: бинарники, образы,
  суммы, SBOM и отчёты; проверяются воспроизводимость и подписи.
- Workflow job/input identifiers — латиницей, русский допустим в `name`.
- Сбой GPG не даёт права отключать подпись. Не копировать обходы
  инструментальных ограничений Claude как действующие разрешения Codex.
